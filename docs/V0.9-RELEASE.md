# FORGE V0.9.0: Media Downloads 2.0

The owner authorized merging, tagging and publishing V0.9.0 so the existing
Windows updater can install it. Publication requires all final tagged-source
release workflows to pass. This source document records that approval and the
update procedure; it does not establish that the release has already been
published. Actual availability and the final commit/run are recorded in the
[GitHub Release](https://github.com/BirthrightPublication/forge/releases/tag/v0.9.0)
and its validation assets.

## Update the existing installation

Finish active processing and stop FORGE using its installed **Stop FORGE.bat**.
Closing the browser alone does not stop the service. Keep the installed
`B:\Forge\Update FORGE.bat` and `B:\Forge\Update-Application.ps1`.

Once V0.9.0 is published as the latest release, open PowerShell and run:

```powershell
New-Item -ItemType Directory -Force 'B:\Forge\Build' | Out-Null
$env:TEMP = 'B:\Forge\Build'
& 'B:\Forge\Update FORGE.bat'
```

The command changes TEMP only for this PowerShell process and its children. The
normal `Build` path avoids the supplied updater's shortened temporary-path bug.
Existing build files stay in place; the updater creates its own staging folder.

Review the plan, confirm `v0.9.0` and enter `UPDATE`. The updater reads GitHub's
latest published release, downloads exactly one
`FORGE-v0.9.0-windows-x64.zip`, checks its matching `.zip.sha256`, and copies the
complete `app/` payload into the existing installation. If the plan shows an
older version, V0.9 is not yet available through that endpoint; do not proceed
assuming the older package contains V0.9. GitHub's automatic source archives are
not installation packages.

After success, open FORGE with its existing launcher, reload the browser with
Ctrl+F5 and confirm version **0.9.0**. Check Local Engine status before starting
new work. Native release acceptance separately verifies a fresh installed
backend's version, import and health; the supplied external updater itself does
not run that complete health check on the owner's computer.

## Preserved files and recovery

The Windows package excludes installed updater files, settings, databases,
credentials, presets, workflows, Black Scripting configurations, queue/history
records, user media/exports, original scripts, model caches, Python environments
and installed tools. Existing speech runtimes and model revisions remain in
place. The application update does not reinstall dependencies or models.

Keep `B:\Forge\Update-Backups` and `B:\Forge\Update-Logs`. If the updater reports
an error, retain its logs and backup before retrying or restoring application
files. The supplied PowerShell script has no automatic post-launch health
rollback; do not erase user data or replace its current database with an older
snapshot as a code-recovery step.

Installations that still use FORGE's legacy offline updater can instead place
the intact `FORGE-v0.9.zip` release asset in `B:\Forge\Build` and run their existing
legacy updater. Those installations retain `Backups` and the existing code-only
rollback procedure. Keep a working GitHub updater in place rather than replacing
it with the separate legacy BAT. Populated V0.8 → V0.9 upgrade and code-only
rollback tests preserve newer plan/import/watch/speech records when V0.8 reopens
the database; see [the recorded integration result](V0.9-UPGRADE-RESULTS.json).

## Changes

- Media Downloads provides Single Download, compact Channel Watch cards and
  Current Download Priority, retaining FORGE's charcoal, warm-white and gold theme.
- Persistent plans deduplicate manual links, selected playlists and watched
  sources. Waiting manual singles precede playlists, then six channel priorities
  with deterministic fair turns. Pending discoveries stay outside the processing
  queue until actual capacity is available.
- Playlist selections, destinations and settings survive pagination and restart.
  Concurrent saves retain independent destination and ordering choices.
- Instant Download approval applies to future eligible discoveries; historical
  review items need separate approval. Stable source folders and source/media
  associations survive renames and retries.
- Download progress uses actual bytes, speed, elapsed time, transfer ETA and
  stages. Unknown totals remain indeterminate. Supported partial transfers and
  verified publication journals support safe recovery without duplicate outputs.
- Internal thumbnail previews, saved-media actions and frozen batch totals remain
  available alongside existing speech, privacy tools and Black Scripting.

## Required release evidence and limitations

The reviewed implementation checkpoint passed 1,135 Python tests with four
platform/optional-environment skips, 506 browser checks, populated upgrade/rollback
and native Windows updater/download checks. These are historical checkpoints;
the final release must run its required checks again from the exact tag.

The release workflow requires the complete tagged Python/browser suites, source
manifest and checksum validation, native unchanged-updater preservation/rejection
cases, and a fresh installed-app version/health check. Native downloader acceptance
requires real yt-dlp, FFmpeg and FFprobe, with all required cases passing and no
skips. The Windows validation asset identifies the exact source and archive.

V0.9 also retains the full native Windows CPU speech gate: original Kokoro Onyx,
Ming, four Bark recognition models, Whisper comparisons and the actual queued
speech pipeline. `SPEECH_ACCEPTANCE.json` and `SPEECH_EVIDENCE.zip` must describe
the same final source and workflow run; earlier V0.8 receipts are not substitutes.
`VALIDATION.json`, the Windows validation receipt and `CHECKSUMS.sha256` record
the final release provenance and asset hashes.

CUDA remains experimental and unverified on owner hardware. This release does
not extend V0.8's physical-GPU exception or claim GPU acceptance. Native downloader
tests use harness-owned local media and explicitly simulated platform metadata;
live YouTube availability, authentication and anti-bot behavior remain unverified.
Resume depends on protocol support. Controlled synthetic CPU speech does not
establish general recognition accuracy, voice similarity or listening quality.
The update package contains no model weights. SHA-256 verifies bytes; it is not
a publisher signature.
