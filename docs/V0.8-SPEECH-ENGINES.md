# Local speech engine adapters and dependency obligations

These adapters are an implementation candidate. Actual native Windows CPU evidence and corrections are tracked in [V0.8-NATIVE-SPEECH-ACCEPTANCE.md](V0.8-NATIVE-SPEECH-ACCEPTANCE.md); the local-only limitation below predates that evidence. Contract/receipt tests are not model inference acceptance. This cloud workspace could read the official GitHub source but the model host returned HTTP 403. No Kokoro or Ming model was downloaded or inferred here; native Windows and physical CUDA model acceptance remain pending.

## Kokoro

- Official runtime: `hexgrad/kokoro`, PyPI `kokoro==0.9.4`.
- Official checkpoint: `hexgrad/Kokoro-82M`, immutable revision resolved at an explicitly approved installation, then recorded and verified.
- Original `voices/am_onyx.pt` is required by the installer. There is no substitute Onyx voice. The library enumerates all compatible `.pt` voice artifacts in that verified snapshot; it does not freeze the installed inventory to a short hand-maintained list.
- Kokoro's original `KModel` loads local config and model weights. Each official voice tensor uses `torch.load(..., weights_only=True)`. A mix is the normalized weighted sum of compatible tensors, not layered audio or a renamed voice.
- `KPipeline` receives the actual blended tensor. The model never downloads a different voice at synthesis time. Cross-engine blends and cross-language blends are rejected.
- Speed is a Kokoro synthesis control. Native emotions, voice cloning, natural-language voice design and expressive vocal tags are not advertised for Kokoro. Effects belong to a separately labeled processing chain.
- The complete approved frontends are installed and checked through real offline phonemization; see [KOKORO-FRONTENDS.md](KOKORO-FRONTENDS.md) for binary/data-source integrity and licensing. Native multilingual neural synthesis is a separate acceptance gate. Original embeddings remain in the voice catalog.

## Ming 0.5b

The runtime source is pinned to official `inclusionAI/Ming-3.0-tts` commit `028c1eace193e7acdb256453da89b6e9207e052b`. Only Python source, license/notice text and the voice-control catalog are extracted. Each byte is checked against that exact Git tree's blob identity before activation. No publisher image/audio examples are bundled in FORGE.

The model checkpoint is `inclusionAI/Ming-3.0-tts-0.5b`. Only local safetensors, JSON/tokenizer data, ONNX speaker extractor and notices are downloaded. Remote Python/pickle model objects are excluded. The official MingTTS task interface is used; tokenizer loading is forced to `trust_remote_code=False, local_files_only=True`.

Task modes are exclusive:

| Mode | Accepted controls |
| --- | --- |
| IP | Exact documented built-in voice invocation ID |
| TTS | Authorized local reference audio, its transcript, English/Chinese; documented inline vocal tags |
| MULTILINGUAL | Authorized local reference audio/transcript and German/Spanish/French/Korean/Japanese language |
| FREEFORM | Natural-language delivery instruction, without another voice/emotion/task control |
| VOICE_DESIGN | Natural-language voice style, without reference audio |
| EMOTION | Authorized reference audio and one of the seven documented native emotion values |
| BASIC | Authorized reference audio and all three documented speed/pitch/volume attributes |
| DIALECT | Authorized reference audio and Sichuanese/Cantonese dialect |

The model is opened through the original MingTTS implementation. FST/pynini normalization is disabled because its upstream Windows installation is not portable; FORGE's source-preserving normalization pipeline can provide explicit replacements. Reference embedding pickle imports are not exposed. A saved reference profile or blend is not model training.

Ming Tiny remains explicitly unavailable on native Windows: its official reference environment needs Python 3.10.15, CUDA 11.8 and Triton. Its 7.9B total parameters cannot be budgeted as only 1.3B active parameters. No automatic Tiny/Qwen model installation is included. Qwen is a capability extension point without a falsely advertised working runtime.

## Installation, integrity and rollback

Each engine uses its own `data/environments/speech-<engine>-<dependency-code-device-fingerprint>` environment. Changes create a new environment fingerprint; completed environments are never modified by pip. CPU and CUDA 12.4 installs are separate explicit choices. CUDA wheels come from the official PyTorch cu124 index (`torch==2.6.0+cu124`, plus matching torchaudio for Ming). The selected runtime identity is recorded with generated segment metadata. An OS-owned cross-process lock serializes install requests. Failed staging environments never become active. Imports and `pip check` must succeed before activation.

An explicit installation approval selects an allowlisted repository, resolves a 40-character immutable snapshot revision, checks every artifact against its publisher LFS SHA-256 or Git blob hash, and records the final local SHA-256 and size. Model receipt verification happens before inference. Completed snapshots are immutable; a damaged unused snapshot must be quarantined before downloading it again. Removing a model quarantines it for recovery and never deletes arbitrary user paths or environments. The application must reject removal while jobs use the model.

Synthesis runs in the engine's isolated Python subprocess with offline mode enabled. Browser/service imports do not import torch or install dependencies. Progress reports real stages and verified files rather than an invented fraction of inference. Model download size and conservative RAM/VRAM planning allowances are separate values. Planning estimates are not measured owner-machine allocations.

## Licensing and redistribution

No model weights, upstream Ming runtime source, reference voices, spaCy models or phonemizer binaries are embedded in the FORGE source/release ZIP by these files. Users explicitly install the selected engine and its dependencies separately. Retain all fetched publisher license and notice files alongside their models and source.

The official Kokoro README describes its checkpoint weights as Apache licensed. The Ming GitHub source metadata declares MIT. This does not establish the licenses of every checkpoint/tokenizer/voice or dependency: the corresponding Hugging Face LICENSE/NOTICE contents were unavailable in this workspace and must be reviewed before any redistribution of those assets. Do not call the entire speech bundle MIT or claim commercial redistribution verification.

Direct runtime obligations also include PyTorch/torchaudio, NumPy, Transformers, Hugging Face Hub, Misaki, spaCy and its English language model, SoundFile/libsndfile, ONNX Runtime and Ming's flow-head dependencies. eSpeak-NG is separately installed and has GPL obligations; FORGE does not silently redistribute it. Optional Japanese and Chinese frontends have their own dependencies and licensing. License metadata and full dependency reports must accompany a validated distribution policy; a permissive weight license does not relicense these components.
