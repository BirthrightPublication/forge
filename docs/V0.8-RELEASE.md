## Update in place

Finish queued work and close FORGE. Preserve your installed `Update FORGE.bat`
and `Update-Application.ps1`. In PowerShell run:

```powershell
New-Item -ItemType Directory -Force 'B:\Forge\Build' | Out-Null
$env:TEMP = 'B:\Forge\Build'
& 'B:\Forge\Update FORGE.bat'
```

Setting TEMP for this PowerShell process avoids the existing external updater's
shortened temporary-path bug; it does not change Windows permanently. Review the
plan and confirm V0.8.0 before entering `UPDATE`. The GitHub updater selects the
single `FORGE-v0.8.0-windows-x64.zip`, verifies its matching `.zip.sha256`, and
installs its `app/` payload. Do not use GitHub's automatic source archives or
replace the existing updater with the separate legacy bootstrap asset.

For installations that still use FORGE's legacy offline Python updater, place
`FORGE-v0.8.zip` intact in `B:\Forge\Build` and run that existing BAT. Retain
`Backups`; the PowerShell updater instead retains `Update-Backups`/`Update-Logs`.
The application update excludes data, models, Python environments, presets,
histories, original scripts and external updater entrypoints. No clean reinstall
is needed. Open FORGE with its existing launcher and reload the browser with
Ctrl+F5. Confirm the displayed version is 0.8.0.

The unchanged PowerShell updater is tested in populated disposable native Windows
installations, including failed validation and preservation cases. This verifies
the supported update contract; it does not establish that the owner's computer
has already been updated or that locally modified updater files are identical.

## Install Kokoro and Ming after updating

The Kokoro/Ming UI installers require FORGE itself to run under Python 3.10–3.12.
An existing Python 3.13 FORGE environment remains usable for existing tools, but
these installers reject it. Installing Python 3.12 alongside it does not switch
FORGE automatically. Preserve the existing environment; arrange a separate
compatible installation interpreter before attempting speech installation.
Each engine creates its own isolated environment and downloads
revision-verified models only after explicit approval. Model weights are not in
the application ZIP. Allow the install job to finish in the Universal Queue.

To check, open PowerShell in the application folder containing `Open FORGE.bat`
and run `& '.\.venv\Scripts\python.exe' --version`. If it reports 3.13, retain that
environment and install 64-bit Python 3.12 alongside it. With FORGE stopped, run
the same reviewed installers from that application folder using Python 3.12:

```powershell
py -3.12 -c "from forge.core import data_directory; from forge.speech_engines import install; install('kokoro', data_directory(), consent=True, device='cpu'); print('Kokoro CPU installed')"
py -3.12 -c "from forge.core import data_directory; from forge.speech_engines import install; install('ming', data_directory(), consent=True, device='cpu'); print('Ming CPU installed')"
```

These commands explicitly approve the separate downloads and do not modify
FORGE's existing `.venv`. They use the normal local FORGE data directory; if you
configured `FORGE_DATA_DIR`, set that same value in this PowerShell session first.
Then reopen FORGE and select CPU. Native acceptance uses these installer functions
under Python 3.12; a Python 3.13 application consuming the separate runtimes has
not been validated on the owner's machine.

1. Open **Text-to-Speech**, select **Kokoro-82M**, and set **Engine settings →
   Compute → CPU**. Open **Model manager → Review installation** and approve it.
2. Select original **Onyx (`am_onyx`)**, enter a short sentence and use **Preview**.
3. Select **Ming-3.0-tts-0.5b**, keep **Compute → CPU**, and install it through the
   same Model manager. Start with **Synthesis task → IP** and an installed built-in
   voice. Reference tasks require permitted local audio and the appropriate mode
   controls. Tiny/podcast mode is unavailable.

## Install Bark recognition

Open **Transcribe**, choose **Recognition engine → Underdog Bark 3.0 · English text**,
select the required Bark variant, set **Processing device → CPU**, then choose
**Review isolated Bark installation** and approve it. The UI installs the CPU
runtime separately from Whisper. Wait for completion before submitting a short
English recording. Bark exports TXT/JSON without aligned timestamps; use Whisper
for timed subtitles, translation or speaker labels. Bark Clean is non-verbatim.

## CPU fallback and limitations

If an experimental CUDA install or job fails, select **CPU** explicitly. For
Kokoro/Ming, use **Model manager → Repair / verify** with CPU selected to install
the separate CPU environment, then submit the job again. For Bark, use its
isolated installation button to ensure the CPU runtime is present and resubmit
with **Processing device → CPU**. Preserve existing CUDA/Whisper environments
and model files; do not delete caches or reinstall FORGE to change compute mode.

CUDA hardware execution, owner-machine speed/memory and human listening quality
remain unverified. Synthetic CPU fixtures do not establish general recognition
accuracy, pronunciation, emotional delivery or voice similarity. Qwen and Ming
Tiny/podcast mode are unavailable; Bark alignment is unavailable. Publisher
notices and separate dependency/dictionary terms remain applicable. SHA-256
checksums verify bytes; they are not publisher signatures.
