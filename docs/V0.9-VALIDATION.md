## Native and publication gates

The development workflow builds the Windows candidate from the pushed source,
executes the supplied unmodified updater against disposable populated installs,
checks fresh installed-app version/health, and runs real downloader acceptance on
Windows x64. Real yt-dlp, FFmpeg and FFprobe are mandatory; skips fail that targeted
gate. No owner's B:\Forge installation is accessed.

Native Windows results must be read from the latest PR checks/artifacts and must
not be inferred from the Linux checks above. V0.9+ release evidence additionally
requires same-source native downloader success with zero failed/skipped cases.

The Windows candidate is FORGE-v0.9.0-windows-x64.zip plus its .zip.sha256, with the
existing app/ contract. Settings, presets, history, models, environments, user
files, original scripts and external updater entrypoints are excluded. Source,
checksum and protected-path verification must pass before publication. Review
artifacts are not GitHub Release assets. Owner approval and the unresolved V0.8
dependency/release decision are required before stable merging, tagging or publishing.
