## Native and publication gates

The development workflow builds the Windows candidate from the pushed source,
executes the supplied unmodified updater against disposable populated installs,
checks fresh installed-app version/health, and runs real downloader acceptance on
Windows x64. Real yt-dlp, FFmpeg and FFprobe are mandatory; skips fail that targeted
gate. No owner's B:\Forge installation is accessed.

The approved-main integration checkpoint at `8b9177d` passed all jobs in
[run 40419970026](https://github.com/BirthrightPublication/forge/actions/runs/40419970026),
including native Windows installation, unchanged-updater preservation and all 30
actual downloader cases with zero failed/skipped cases and clean same-source
provenance. Results for later source must be read from its
latest PR checks/artifacts, not inferred from that checkpoint or the Linux checks.
V0.9+ release evidence additionally requires same-source native downloader success
with zero failed/skipped cases.

The Windows candidate is FORGE-v0.9.0-windows-x64.zip plus its .zip.sha256, with the
existing app/ contract. Settings, presets, history, models, environments, user
files, original scripts and external updater entrypoints are excluded. Source,
checksum and protected-path verification must pass before publication. Review
artifacts are not GitHub Release assets. V0.9 owner approval and its final release
checks are required before stable merging, tagging or publishing. The V0.8-specific
hardware exception is not silently applied to V0.9.
