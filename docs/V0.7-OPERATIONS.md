# FORGE V0.7 operations and implementation

V0.7 is a development candidate based on main commit `ddd49eb2e10f290708a99bf74de7dc088eff329f`. The approved V0.6 release and its assets remain unchanged. Review/approval precedes V0.7 merge, tag and publication.

## Downloads and sources

Download Studio uses the existing `Download` model, Universal Queue, isolated yt-dlp worker, FFprobe validation and collision-safe output publisher. Legacy Audio/Video routes and compatible presets remain usable. Saved directories appear immediately; Browse uses the native picker and Open uses the guarded local filesystem API. Default destination is the user's Downloads/FORGE folder. Named favorites, default and last-used destinations live in the existing local database.

Watch a YouTube channel, handle or playlist. Registration contacts YouTube and inspects bounded metadata. Default import is future uploads only; Latest N, publication-date and manual historical review are explicit choices. Historical pagination never starts downloads automatically. Channels inspect videos, Shorts and streams separately, at most 200 entries per tab per check; playlists inspect at most 200 entries. Older discovery is paged, not an exhaustive initial crawl. Unknown publication dates cannot qualify for date-based imports; where dates are absent, Latest N follows extractor ordering. Unknown totals remain unknown.

The service loads enabled sources asynchronously at startup, with at most two discovery subprocesses and a 60-second hard deadline per metadata subprocess. Optional public YouTube thumbnails use an allowlisted CDN, a separate five-second timeout, a one-MiB transfer bound and verified local PNG conversion. Monitoring runs only while FORGE runs. Intervals start at 15 minutes; failed network requests back off, and explicit authentication/access errors suspend automatic source checks until manual refresh or configuration repair. This is polling, not push notification or a guarantee of immediate discovery.

`source_watch.py` declares adapter capabilities; `source_probe.py` isolates bounded metadata extraction. YouTube is the sole shipped watch adapter. Generic manual URLs retain yt-dlp's supported-source behavior. RSS/Atom, podcast-feed, Twitch and Bluesky watch adapters are extension points, not working claims.

The additive `watch_sources`, `watch_media` and `watch_discovery` tables separate discovery from queue history. Media IDs deduplicate across sources, renames, repeated checks and restarts. Job creation and media association share a SQLite transaction. Queue retries update that association; deleting old queue records does not delete discovered media. Automatic retry is opt-in, limited to three attempts and transient classified failures. Skip is permanent unless the user explicitly selects Download now.

Rules choose format, resolution, metadata, subtitles, filename, destination and priority at source/content-type level. Priority affects waiting jobs, never preempts active work. Stable source IDs name channel folders. Audio output uses Audio folders; video types use Videos/Shorts/Streams/Premieres etc. Upcoming entries wait; unclassified entries require review unless explicitly enabled. Live capture requires an explicit live-capture policy and enabled content type. Shorts detection uses explicit source metadata/tab identity, never duration alone. Completed premieres, clips and podcasts are classified only when source metadata identifies them. The UI retains unsupported/unknown classifications truthfully.

Successful output records retain measured execution/stage durations, sizes and SHA-256. Mark archived requires a byte-for-byte hash match to a previously worker-verified output for that media; filenames alone do not qualify. No unrelated folders are indexed. Private partial downloads remain under application-data `download-cache`, keyed by job/source/options identity, for supported HTTP/fragment resumption. Servers may refuse ranges and restart transfers; failed `.part` files are never published as complete output.

Authentication uses an explicitly selected authorized local cookies file. Workers and metadata probes operate on a private temporary copy and do not rewrite the owner's file. Ordinary presets/working preferences exclude cookies. Download diagnostics distinguish authentication, unavailable media, rate limiting, runtime/EJS, format, network and FFmpeg errors without logging raw cookies or extractor messages. Dependency repairs use the existing approved Downloads class. Node 22+ or Deno 2.3+ is required by the tested yt-dlp runtime integration; system runtimes remain user-managed through official downloads. Updating the engine does not bypass account/network restrictions.

A completed download retains source identity in the job payload and independent verified output metadata, providing a future boundary for invoking saved linear Black Scripting. V0.7 adds no unfinished branching engine.

## Updates and recovery

The header icon toggles a compact, nonmodal right-side panel. Application releases appear separately from compatible component batches. Optional uninstalled models do not inflate the actionable count. The panel shows current/available version, changelog, last check, stages and local maintenance history. Only actual known byte totals produce proportional transfer progress. GitHub mode verifies HTTPS publisher paths, SHA-256 and the source manifest; it is not a production digital signature. The existing pinned-key manifest contract remains available for a future approved signing policy.

Pending maintenance shows a banner across workspaces and can be cancelled before shutdown. Active jobs finish; paused queued jobs are preserved rather than waiting forever. Pending requests expire after 30 minutes. Compatible automatic repairs still require prior approval of their registered dependency class. New application versions always require explicit consent.

The independent Windows maintenance runner exposes only a read-only status endpoint on the original loopback port while the backend is stopped. It accepts existing browser-session cookie hashes, rejects cross-origin requests and stops before the application rebinds the port. This lets the same Updates panel show actual backup/install stages without importing a potentially changing application environment.

The runner waits on the exact old process handle/creation time, stages compatible wheels, backs up environments, verifies package contents and invokes the existing journaled updater. It then recompiles only application Python directories using checked-hash bytecode, verifies a fresh isolated import, starts the correct installation with the existing data directory/port, and checks runtime root, new PID, imported/running/health versions. Windows virtual-environment redirectors are handled by verifying the backend’s current process ancestry to the owned launcher handle; port or version matching alone is insufficient. Queue dispatch stays paused until health passes. Success is recorded only after validation. A failed restart terminates only the runner's owned child process tree and retains backups with an actionable recovery message.

The launcher refuses an existing service with a different root or version. Finish jobs and use Stop FORGE.bat before reopening if a manual/external update left an older backend alive. It never silently opens that older backend or stops another installation.

The external `B:\Forge\Update FORGE.bat` and `Update-Application.ps1` remain untouched. For recovery, use their existing backup/restore procedure. Legacy code rollback remains available through `scripts/update.py --root B:\Forge --rollback --yes --no-launch` after stopping FORGE; review the target backup first. Interrupted dependency maintenance retains `py -3 scripts/managed_install.py --recover`. Do not extract another installation beside the active root or replace a working GitHub updater with the legacy BAT.

## Navigation and addresses

Settings replaces the sidebar queue slot; the header and bottom queue dock remain. Overview is a compatible legacy route, not a normal landing page. Search stays left aligned with Ctrl+K. Tooltips appear beside compact icons without clipping. The brand version comes from the running backend. Black Scripting enters its full-width workspace and exits to the previous tool, preserving drafts and in-memory address fields.

Addresses are synthetic samples, not verified deliverable residences. US, UK, Canada, Australia, Germany and Japan have reviewed city/region/postal sample groups. Per-field regeneration respects locks; dependent geographic fields may change together, or regeneration explains why no compatible alternative exists. Copy controls support individual fields, full addresses and labeled fields. Optional test phone ranges are supplied only for US/CA/UK/AU. Presets save configuration and lock names, never generated addresses. Addresses remain in tab memory while switching to external forms; Clear/page close removes them. Password/token clearing behavior remains unchanged.

## Preservation and limitations

No migration deletes existing data. Models, environments, CUDA diagnostics, original media, exports, settings, presets, Black Scripting, queued/history records, credentials and update backups remain local. Windows release ZIPs retain a single `app/` payload and protected-path filtering; release ZIPs never enter the source tree.

Live YouTube access depends on the user's network, source permissions and available extractor metadata. The cloud live metadata probe was blocked by connectivity. Local HTTP media tests and synthetic source fixtures do not establish live YouTube success. Physical GPU/CUDA and the user's actual B: drive are not available in the cloud. See the validation report for native Windows and review-build evidence.
