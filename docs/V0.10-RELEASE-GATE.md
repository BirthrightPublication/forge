# V0.10 stable release acceptance gate

V0.10 remains an unreleased development candidate. The current source has no
reviewed OPUS/Qwen model pins or production model inventory. Stable publication
therefore stops immediately with the missing component named, before requesting
external evidence or downloading a model. A UI, synthetic orchestration tests,
or prior V0.8 speech acceptance cannot satisfy this gate.

`scripts/check_dubbing_release.py` uses only the Python standard library. It
does not install packages, execute model-host code, perform inference, or create
acceptance claims. Candidate `windows-release.yml` calls with `build_only: true`
can still build/test application packages. Both stable publication paths require
this additional gate for every tag from `v0.10.0` onward; earlier tags retain
their established gates. No V0.10 physical GPU exception has been approved.

## Reviewed source inventory

After publisher access and license review are complete, add the production file
`forge/dubbing_release_inventory.json` and include it, its referenced wheel lock,
requirements, and `forge/dubbing_models.py` in `release-manifest.json`. Do not
populate this file with example pins or guesses. The checker verifies these
source-file hashes without executing application code.

The inventory is schema 1, has `license_reviewed: true`, and a `components`
mapping containing `opus-en-ru` and `qwen3-tts-0.6b-base`. Each component needs:

- `parts`: bounded complete part descriptors, each with `repository`, exact
  40-character `revision` matching the literal `MODEL_PINS` source mapping,
  `license: {id, reviewed: true, commercial_use: true}`, and `artifacts` entries
  `{path, sha256, size}` for every selected checkpoint/tokenizer/license file.
  The required primary repositories are `Helsinki-NLP/opus-mt-en-ru` and
  `Qwen/Qwen3-TTS-12Hz-0.6B-Base`. Every part includes its actual license/notice
  artifact. OPUS includes config, weights, source/target SPM and vocabulary.
  Qwen also includes generation/tokenizer configs and the embedded speech
  tokenizer config and weights.
- `runtime`: `requirements: "scripts/requirements-dubbing-core.txt"`, its
  `requirements_sha256`, `wheel_inventory`, that file's
  `wheel_inventory_sha256`, and `device` (`cpu` or `cuda`). The wheel filename
  must match the installer's actual registered profile, for example
  `forge/dubbing_wheel_locks/requirements-dubbing-core-windows-x64-py312-cpu.json`.

The native wheel lock must record `schema: 1`,
`profile: "requirements-dubbing-core"`, `system: "windows"`,
`architecture: "x64"`, `python_version` (`3.11` or `3.12`), the matching
`device`, `native_windows_execution: true`, `cross_resolved: false`,
`reviewed: true`, `dependency_closure_complete: true`, and the requirements hash.
Its complete `wheels` list records each package's exact `package`, `version`,
wheel `name`, `sha256`, positive `size`, and reviewed `license`; `download_bytes`
must equal their total. Linux-only or cross-resolved metadata is insufficient.
Do not set native/review flags before performing those checks.

## Separate real acceptance artifact

Run the real acceptance on the exact source commit to be tagged. The separate
Actions run must belong to `BirthrightPublication/forge`, have that exact
`head_sha`, and finish with `status: completed`, `conclusion: success`. Upload
exactly one unexpired artifact named `dubbing-acceptance-v0.10.0` (substitute the
actual tag). It contains a root `DUBBING_ACCEPTANCE.json` and its evidence reports.
Use modern Actions artifacts which expose a SHA-256 digest through GitHub's API.

Select that successful run through the optional `dubbing_acceptance_run_id`
workflow-dispatch/reusable-workflow input, or repository variable
`FORGE_DUBBING_ACCEPTANCE_RUN_ID`. Tag/release events use the repository variable.
An absent run ID or absent proof fails; it never means skip. The read-only gate
verifies the authenticated run/artifact metadata, checks the downloaded artifact
digest, and extracts it with file-count/size, traversal, link, Windows reparse
point and collision safeguards. GitHub credentials are not forwarded to the
signed artifact host.

The acceptance JSON needs these exact fields:

```text
schema: 1
app: "FORGE"
status: "passed"
repository: "BirthrightPublication/forge"
actions_run_id: "<the separate successful decimal run ID>"
tag: "v0.10.0"
source_commit: "<exact 40-character tagged commit>"
source_manifest_sha256: "<SHA-256 of that commit's release-manifest.json bytes>"
model_inventory_sha256: "<SHA-256 of dubbing_release_inventory.json>"
model_revisions:
  opus-en-ru:
    Helsinki-NLP/opus-mt-en-ru: "<reviewed exact revision>"
  qwen3-tts-0.6b-base:
    Qwen/Qwen3-TTS-12Hz-0.6B-Base: "<reviewed exact revision>"
wheel_inventory_sha256:
  opus-en-ru: "<matching reviewed native wheel inventory SHA-256>"
  qwen3-tts-0.6b-base: "<matching reviewed native wheel inventory SHA-256>"
native_windows_execution: true
inference_substituted: false
synthetic_only: false
reference_consent: true
private_inputs_not_embedded: true
artifacts:
  - path: "reports/native-acceptance.json"
    sha256: "<actual report SHA-256>"
    size: <actual report byte count>
checks: <the individually verified checks below>
physical_gpu: <separate actual GPU results below>
```

This is a contract outline, not a passing report. Placeholder text fails
validation. Additional model parts must appear in `model_revisions` exactly as
in the reviewed source inventory. Report paths are relative to the artifact
root. Every reported file must exist and match its SHA-256 and size. The verifier
returns the exact identity fields with the `inventory` command for comparison.

Every check is an object with `status: "passed"` and a nonempty `evidence` list
of paths present in the verified `artifacts` list. All of these are mandatory:

| Check key | Additional required fields/evidence |
| --- | --- |
| `gui_recommended_install` | `through_forge_gui: true`, `installed_components` containing both recommended component IDs; actual approval/download/install receipts |
| `restart_model_persistence` | `verified_after_restart: true`; model/runtime receipts remain valid after restart |
| `timed_english_asr` | `inference_tested: true`, `timings_verified: true`, positive integer `segment_count`; actual timed recognition |
| `russian_translation` | `inference_tested: true`, `target_language: "ru"`; actual translated output and preserved segment/timing evidence |
| `reference_russian_tts` | `inference_tested: true`, `language: "ru"`, `reference_consent: true`, actual `reference_sha256`; real permitted-reference Russian synthesis |
| `playable_outputs` | `decoded_and_probed: true`; actual decoded/probed speech and media results |
| `windows_v09_upgrade` | Normal existing updater V0.9 → the tagged application |
| `protected_userdata_preservation` | Settings, references, profiles, projects, model/environment caches, presets, Black Scripting, histories, credentials and media preserved |
| `external_windows_updater` | Existing updater entrypoints preserved and exercised |
| `rollback_recovery` | Failed-install/restart rollback and retained protected data |
| `running_backend_version` | `version: "0.10.0"`; owned restarted process and backend health actually report this version |

`physical_gpu` separately needs `status: "passed"`, verified `evidence` paths,
`physical_gpu_tested: true`, `inference_tested: true`, the actual `device_name`,
and positive integer `peak_vram_bytes`. Record actual hardware/driver/model
revisions, tested operations, timings and memory observations in the referenced
report. GPU presence, successful import/allocation, a synthetic kernel alone,
untested status, or the V0.8 CPU exception does not pass V0.10 acceptance. Owner
RTX 5080 claims still require measurements on that hardware.

## Evidence privacy and publication

Use owned, intentionally prepared test inputs and record identifiable-reference
permission. `synthetic_only: false` means actual model inference occurred; an
owned generated fixture video can still be used as controlled input. The
validator's synthetic unit fixtures are never acceptance evidence.

Only sanitized JSON/XML/TXT/LOG reports and reviewed PNG screenshots may be
referenced as evidence. Do not include reference audio, private media,
unpublished scripts, OAuth credentials/tokens, signed resumable URLs, account
secrets, or identifying machine/user paths. Report input hashes and measured
results instead of embedding private inputs. Review screenshots and logs before
uploading: these reports become public release assets after approval.

The passed gate produces `DUBBING_RELEASE_GATE.json`, retaining the source,
manifest, inventory, model, native-wheel and external Actions artifact identities.
It also produces `DUBBING_EVIDENCE.zip` containing only acceptance JSON and the
verified reports. That archive's hash and size are bound to the gate receipt.
The two publication paths retain and download-verify these three additional
release assets without replacing historical assets:

- `DUBBING_ACCEPTANCE.json`
- `DUBBING_RELEASE_GATE.json`
- `DUBBING_EVIDENCE.zip`

These do not replace the single `FORGE-v0.10.0-windows-x64.zip`, its matching
`.zip.sha256`, or the existing Windows package/updater validation. The evidence
ZIP's name does not match the Windows installer selector. No release is created
by the checker itself; final owner approval, existing tagged-source checks and
successful publication are still required.
