# Install the published FORGE V0.6.0 update

Release: https://github.com/BirthrightPublication/forge/releases/tag/v0.6.0

Keep the installed `B:\Forge\Update FORGE.bat` and `Update-Application.ps1`.
The Windows ZIP contains `app/`; user files, settings, presets, models,
environments and history are excluded. Finish active jobs and stop FORGE before
updating. Leave existing environments and data folders in place.

From PowerShell, use a canonical temporary directory so the existing updater
does not miscalculate paths containing Windows 8.3 aliases:

```powershell
$env:TEMP = 'B:\Forge\Build'
& 'B:\Forge\Update FORGE.bat'
```

Type `UPDATE` when prompted. Only after the updater reports success, run this
one-time application bytecode refresh **before reopening FORGE**:

```powershell
& 'B:\Forge\.venv\Scripts\python.exe' -m compileall --invalidation-mode checked-hash -q -f 'B:\Forge\forge' 'B:\Forge\scripts' 'B:\Forge\launcher.py' 'B:\Forge\server.py'
if ($LASTEXITCODE -ne 0) { throw 'Cache refresh failed. Keep FORGE stopped and retain the updater backup.' }
```

This recompiles only disposable Python caches beside application code. It does
not reinstall packages, modify the Python environment, or touch settings,
presets, models, Black Scripting definitions, queue history or user files.

Why the extra step: the previously published V0.5 and V0.6 Windows ZIPs use the
same fixed timestamps. The supplied updater preserves timestamps and old Python
caches. When an updated Python file has the same length, Python can execute its
old cached code. Forced compilation in checked-hash mode refreshes that code and
validates subsequent source changes by content. Both published assets and their
tags remain unchanged. New packages use distinct, deterministic version-derived
timestamps, with cached-upgrade regression tests in Linux and native Windows.

After the refresh, reopen FORGE normally and confirm version `0.6.0`. The updater
retains overwritten application files and its rollback manifest in
`B:\Forge\Update-Backups`. If rolling back using the external updater, refresh
application bytecode again before starting the restored application.

The signed-manifest contract is tested, but production signing keys are not
configured; this release uses HTTPS and SHA-256 verification. Physical GPU/CUDA
execution and live model downloads on the owner's computer remain unverified.
