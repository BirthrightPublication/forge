# FORGE V0.10 development candidate

## Status and baseline

This is development documentation, not a release announcement. Work is on
`development/v0.10-dubbing-studio`, based on approved V0.9 production source
`2a022f2992ba32e7cd42d364a1e193d144b7ca34`. The authoritative repository is
<https://github.com/BirthrightPublication/forge>. V0.10 has not received final
owner approval for merging, tagging or publication.

See [candidate validation](V0.10-VALIDATION.md),
[draft PR #10](https://github.com/BirthrightPublication/forge/pull/10), and the
[stable-publication evidence contract](V0.10-RELEASE-GATE.md).

The new APIs, persistent project/queue integration, local media processing,
managed-model controller, optional model adapters, interface and supported
YouTube publishing implementation are source changes. They do not establish
that a complete neural dubbing workflow has passed acceptance. Hugging Face
requests currently receive a cloud-proxy `CONNECT 403`. Exact model checkpoint
pins and complete artifact/license inventories are therefore not populated;
unverified components remain unavailable. Actual model inference, native Windows
installation/restart acceptance, owner RTX 5080 measurements and live Google
OAuth/YouTube upload acceptance remain outstanding. See
[the model inventory](V0.10-MODEL-INVENTORY.md) for individual gates.

## Implemented workflow

Dubbing Studio adds a compact dark Birthright workspace with original-video
preview, English/Russian segment editing, speaker/reference selection, timeline,
setup, voice, export and publishing panels. Project panel preferences and last
workspace choices persist. Import registers an existing playable local video;
it does not replace the original file. Source identity, selected references and
prior artifacts are checked again in the worker.

The production sequence is English recognition, English-to-Russian translation,
explicit script review, permitted Russian reference synthesis, measured timing,
mix/master, optional lip sync, encode and export. Each step uses the existing
universal queue and worker subprocesses. A render never initiates an upload.

- Faithful, Localized Commentary (default) and Alternative Commentary are saved
  project modes. OPUS-MT performs translation; it is not an instruction-following
  localization editor. Localized phrasing and substantive alternative commentary
  require editable text and human review. The implementation does not claim an
  additional generative editing model.
- Stable segment IDs preserve source timing, speaker assignments and English
  text. Glossary substitutions and selected-segment regeneration are supported.
  Manual Russian edits are retained unless replacement is explicitly requested.
- Final narration/render stages require the reviewed project and approved voice
  revisions. A bounded preview does not approve the final script. Changing
  relevant text, voices or settings invalidates affected downstream work.
- Voice-reference preparation uses a non-silent candidate window, not speaker
  identification. Listen to the candidate and explicitly approve a permitted
  speaker/reference before production. Separate speakers can use separate saved
  reference profiles. Qwen Base is a reference-cloning adapter, not a catalog of
  built-in Russian narrators. Original Kokoro Onyx IDs/tensors remain unchanged;
  no Russian Onyx capability is claimed.
- Preserve, natural, balanced and manual timing strategies use measured speech
  durations, pauses and bounded FFmpeg tempo correction. Overlaps, excessive
  duration and unsupported stretch are reported for review. Video extension
  requires an explicit option when narration exceeds the source.
- Original-track gain/ducking, manually imported background/music/vocal stems,
  loudness processing and existing audio effects are integrated. An intact
  original track still contains its English speech. Ducking is not source
  separation, and independent music/background controls require actual stems.
- Optional source separation and MuseTalk rendering have real runtime adapters
  and verification gates, but their checkpoint/inference acceptance is pending.
  Lip sync is off by default. Every selected face needs consent; automatic face
  proposals are not identity recognition or proof of the active speaker. A
  5–10-second preview and selected-scene rendering are supported by the adapter.
  A lip-sync failure preserves original footage and completed Russian audio so
  an audio-only dubbed export remains possible.
- Exports include MP4/MKV, WAV/FLAC, Russian SRT/VTT/transcript, editable metadata,
  optional bilingual JSON, provenance and a private project ZIP. Codec,
  subtitle, resolution and frame-rate choices determine whether video is copied
  or re-encoded. Media streams and durations are probed before completion.

The project ZIP is a private local backup, not a release asset. It can contain
the original media, generated segments and permitted voice references. Keep it
secure. OAuth credentials and installed models are excluded. A self-contained
project-import/recovery wizard is not claimed by the existence of this export.

## Architecture and persistence

| Boundary | Implementation |
| --- | --- |
| Project API, plans and review | `forge/dubbing_api.py`, `dubbing_options.py` |
| Additive project/revision/run/artifact records | `forge/dubbing_store.py` |
| Stage orchestration and immutable segment cache | `forge/dubbing_pipeline.py` |
| Measured alignment, mixing and export | `forge/dubbing_audio.py` |
| Managed models and isolated subprocess invocation | `forge/dubbing_models.py`, `scripts/dubbing_runtime.py` |
| Optional visuals and source separation | `forge/dubbing_visual.py`, `dubbing_separation.py`, `scripts/dubbing_visual_runtime.py` |
| Publishing profiles/review/history and OAuth | `forge/language_publishing.py`, `publishing_oauth.py` |
| Browser workspace | `web/dubbing_v10.js`, `dubbing_v10.css` |

Schema additions preserve existing tables and histories. Optimistic revisions
reject stale saves; worker results merge only unchanged relevant inputs and
retain newer edits. Queued work freezes source, model, glossary and permitted
voice revisions. Verified content-addressed segment audio is reused after
partial failure; a corrupt cache is retained for diagnosis and not counted as
a hit. Durable stage result manifests let the existing queue reconcile work
after restart. Black Scripting uses registered linear production stages and
review gates, not a second scheduler. Publishing still requires its own explicit
reviewed action.

Private working files, caches and reports live below the existing FORGE data
directory. Existing media, downloads, TTS projects, settings, presets, Black
Scripting definitions, histories, environments and model caches remain protected
upgrade inputs. Heavy media work and model inference run outside application
database/scheduler locks.

## Guided installation and maintenance

The intended Windows installation remains `B:\Forge`, with build/download
workspace `B:\Forge\Build`. Once an approved V0.10 release exists, use the
existing Updates interface or installed `Update FORGE.bat`; do not install this
development branch over an active private installation to substitute for release
acceptance.

1. Open Dubbing Studio → Set Up Dubbing Studio. The summary inspects OS,
   architecture, application Python, RAM/disk, FFmpeg/FFprobe, NVIDIA driver/VRAM,
   existing compatible Whisper and the new managed packs.
2. Install Recommended requests a bounded plan with selected components,
   destination, verified download totals and conservative storage allowance.
   Approve that plan before installation. If publisher pins, complete binary
   wheel inventories or license approval are missing, a complete quote cannot
   be provided and installation is refused. Do not treat an unknown size as zero.
3. Verified artifacts download into persistent managed storage. Supported Range
   continuation is checked, artifacts are hashed and activation is atomic.
   Verify, Repair, Test Model, compatibility checks, approved storage moves and
   Remove Unused operate through queued managed actions. Referenced revisions
   and existing environments are retained.
4. Model dependencies use separate immutable environments. An incompatible
   Windows application Python can be paired with a pinned managed CPython 3.12
   runtime under FORGE data; no system Python, registry or PATH change is made.
   Windows binary-wheel/native-runtime acceptance is still required before
   describing this path as verified on the owner's installation.

Application-update preflight reports current health, work and storage. The
maintenance host coordinates job draining, process shutdown, backup, verified
code installation and restart. It verifies a fresh import, owned new process,
installation root, runtime/state/health versions and queue-preference restoration
before recording success. Browser polling is bounded and its completed-version
reload is deduplicated; a changed on-disk version alone is insufficient.

Interrupted installations expose a controlled recovery/repair action when the
journal and owned-process checks allow it. Failed restart validation attempts to
restore the verified previous application and checks that backend again. If
automatic recovery cannot be verified, retain the diagnostic/journal and backups;
do not report success or clear protected user directories. The installed
external Windows updater remains the recovery path. No code in this development
task accesses or modifies the owner's `B:\Forge` installation.

## Russian channel publishing

Language Publishing Profiles save Russian defaults, channel identity, metadata
templates, preferred voice/style/export settings and timezone (default
`Europe/Moscow`). New visibility defaults to Private. Metadata is editable;
translated titles/descriptions/tags/chapters require review and do not promise
audience reach, ranking or analytics functionality.

Connect YouTube Channel uses a user-registered Google installed-desktop OAuth
client, PKCE/state and a temporary owned `127.0.0.1` callback listener. FORGE's
ordinary authorization/CSRF rules remain intact. Google developer registration,
test-user configuration, consent verification and upload audit/limits still
apply. FORGE does not ask for an account password or bypass Google's approval.
Credentials and resumable session URLs use Windows current-user DPAPI and are
excluded from projects, presets, job payloads, metadata and source. Non-Windows
production credential storage has no plaintext fallback.

The interface shows the authorized channel name, avatar and stable channel ID.
Changed accounts need confirmation. An ambiguous multi-channel OAuth identity
must be reconnected in the intended channel context. The supported
`videos.insert` operation cannot choose an arbitrary channel by setting
`snippet.channelId`.

Before Publish/Schedule, a short-lived review capability binds the actual file
hash, profile/connection revision, exact channel, title, visibility, timezone-aware
future schedule, audience/disclosure and subtitle choices. Explicit approval
creates one durable queue/history record atomically. The transfer uses resumable
chunks and acknowledged byte progress, bounded network timeouts and session
recovery. The accepted video is checked with `videos.list` against the approved
channel before captions or reviewed visibility/schedule changes. Initial API
insertion is Private even when a later Public/Schedule change was reviewed.
Caption failure preserves the accepted video ID so retry does not upload a
duplicate. A completed record is not republished by replaying an old review.

Subtitles use supported `captions.insert` authorization. Scheduling keeps the
video private until the confirmed publish time and requires compatible API
permissions/state. Manually managed alternate audio tracks and every YouTube
Studio feature are not exposed as supported API operations. If API setup or
publishing is unavailable, Export for YouTube creates local metadata/subtitle
files and Open YouTube Studio opens <https://studio.youtube.com/> after an
explicit action; the user performs the upload there. Nothing is uploaded by
that fallback's export action.

## Validation and remaining release gates

Tests distinguish pure contracts, authenticated API/queue persistence, browser
interaction, real FFmpeg synthetic-media processing and actual model/native
hardware operation. Model stubs and tone audio prove orchestration, not Russian
speech quality, neural translation or lip-sync inference.

Relevant suites include `test_dubbing_store_v10.py`, `test_dubbing_review_v10.py`,
`test_dubbing_queue_v10.py`, `test_dubbing_black_v10.py`,
`test_dubbing_models_v10.py`, `test_dubbing_production_v10.py`,
`test_dubbing_visual_v10.py`, `test_language_publishing_v10.py`,
`test_v10_maintenance.py`, `test_v10_hotfixes.py`, `test_v10_voice_preview.py`,
`browser_v10_check.py`, `browser_v10_hotfixes.py` and `integration_upgrade_v10.py`.
The latter hotfix coverage retains chapter/scope selection, complete transcription
errors, maintenance reload guards and explicit voice-card preview recipes while
preserving saved narrator/dialogue assignments and original Onyx tensors.

The publishing tests use an owned local HTTP OAuth/resumable API fixture and
playable FFmpeg media, not live Google authorization or uploads. The native DPAPI
test is skipped on Linux. New model acceptance workflow jobs resolve native
Windows Python 3.12 wheel inventories and exercise the managed-runtime bootstrap;
writing a workflow does not establish a successful run or GPU inference.

Before calling V0.10 complete, retain passing evidence for exact publisher pins
and licenses, GUI pack installation/restart, real English ASR/Russian translation
and reference synthesis, optional neural features, Windows V0.9 upgrade/rollback
and unchanged updater/protected-data acceptance, required regressions and
authorized private YouTube acceptance. Measure RTX 5080 behavior on actual owner
hardware before making hardware-specific performance claims. Final test counts,
source SHA and any remote workflow results belong in the final candidate report.

After all mandatory checks and owner approval, release packaging must use the
approved tagged source, an `app/` payload, exactly one
`FORGE-v0.10.0-windows-x64.zip` and matching
`FORGE-v0.10.0-windows-x64.zip.sha256`. Preserve historical releases and external
updater entrypoints. No final V0.10 tag, release asset or publication is claimed
by this document.
