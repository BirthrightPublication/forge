# V0.6 implementation and acceptance

Baseline: `a1dcaef95428886d57074cea23fe4d4ec04a3f5c` (V0.5 plus approved Windows packaging fixes).
Development branch: `development/v0.6-automation`.
Baseline verification: 573 Python tests passed in the restored cloud environment.

Work proceeds through persistent model/dependency management, managed maintenance,
central updates, working preferences, scheduling/timing, and compact interface changes.
Preserve the existing authenticated local API, process isolation, Black Scripting,
privacy tools, data directory, and both Windows updater contracts.

Model downloads resolve an immutable publisher revision on first installation and
retain it locally. Existing compatible snapshots remain usable offline. A subsequent
upstream revision must be explicitly selected through Updates. Downloads and model
verification never send user media. Cache locks span worker processes and survive
process crashes without stale ownership. Completed manifests are atomically published.

CUDA enumeration, runtime loading, and inference are separate evidence. No Windows
GPU is attached to this cloud runner. Never describe mocked CUDA tests as an RTX 5080
hardware test. The runner proxy currently denies Hugging Face metadata requests,
including after permission escalation; record real-download coverage separately.

Keep process isolation until comparative measurements justify a shared model worker.
Use resource admission and serialize identical GPU models to avoid duplicate weights.
Measure job/stage durations with a monotonic clock; persist elapsed values, not that
clock's process-specific origin. Never invent durations for historical records.

Working preferences use explicit safe fields and are separate from named presets.
Do not persist text payloads, prompts, credentials, cookies, or generated secrets.

Before release: full Python/browser regressions, cache/failure/recovery tests,
incremental upgrades and rollback, exact-tag package validation, native Windows
updater acceptance, source/privacy review, pushed branch verification, and user
approval to merge. Publish only after these gates; keep the release pending otherwise.
