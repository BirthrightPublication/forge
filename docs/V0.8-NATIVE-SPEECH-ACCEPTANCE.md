## Actual runtime failures and corrections

[Run 40390928845](https://github.com/BirthrightPublication/forge/actions/runs/40390928845)
downloaded real checkpoints and exposed two failures missed by contract tests:

- Kokoro's fresh environment lacked `click`, imported by spaCy's command modules.
  Its isolated requirements now include the compatible explicit pin.
- Ming's pinned implementation combines BF16 model parameters with FP32 speaker
  inputs outside CUDA autocast. The CPU adapter now uses FP32 parameters and prompt
  encoding; the upstream CUDA BF16 path remains separate and unverified on hardware.

The initial Bark jobs could not start inference because the failed Kokoro job had
not produced its fixture. Those missing-fixture failures are not Bark accuracy data.

## Actual CPU inference checkpoint

[Run 40392333153](https://github.com/BirthrightPublication/forge/actions/runs/40392333153)
then passed original Onyx generation, an actual compatible weighted voice blend,
original embedding preservation and offline repeat. The generated reference is
11.85 seconds of original synthetic English test prose, with nonzero PCM and no
clipping. A repeat produced identical PCM on that runner; this is not a claim of
bit-identical output across different devices or runtime versions.

Ming's eight documented mode calls completed on native Windows CPU: IP, reference
TTS, voice design, EMOTION, FREEFORM, BASIC attributes, MULTILINGUAL and DIALECT,
plus offline reuse. Signal checks establish real non-silent output, not a human
rating of emotional delivery, cloning similarity or pronunciation quality.

All four Bark models completed actual clean and repeated-long recognition with
zero normalized word errors on the short controlled English fixture. The four-window
long case preserved ordering. This small synthetic test does not establish accuracy
on owner media, real accents or arbitrary noise. Raw punctuation/case errors and
actual processing time/process-memory measurements are recorded separately.

The Plus/Pro comparison jobs still failed because the newly created Whisper
environment lacked `pkg_resources`, imported by pinned CTranslate2 4.6.0. The
transcription requirements now pin compatible setuptools explicitly. No original
Whisper environment, model or preset was replaced by these disposable tests.

A separate Linux review run timed out during system-media dependency setup before
Python tests. Review setup now uses bounded commands and signed official Ubuntu
HTTPS sources, retaining diagnostics. This was infrastructure setup, not an
application-code test failure.

[Review run 40397808418](https://github.com/BirthrightPublication/forge/actions/runs/40397808418)
then passed application regression/browser review, native Windows contracts and
the unchanged external updater in a populated disposable installation. The expanded
model run passed Ming again but exposed a fresh Kokoro frontend resolver failure:
`num2words` requires source-only `docopt`. That exact MIT-licensed artifact is now
reviewed and hash-pinned alongside the existing pure-Python/data build exceptions;
arbitrary source builds remain disabled. The complete Windows-target dependency
resolution and the resulting native runtime are separate checks.

## Additional acceptance gates

The next native run adds complete Kokoro phonemizer/voice checks, controlled 20 dB
noise, a verified synthetic British voice, Whisper comparisons and actual speech
through the authenticated application API/queue with master processing and segment
cache reuse. Their results must be read from the latest workflow, not inferred from
the earlier checkpoint above.

For V0.8 and subsequent releases, both the main publisher and standalone Windows
asset backfill require actual CPU model acceptance for the exact tagged source.
The gate requires both full TTS receipts, all four Bark variants, both Whisper
comparisons and the real API/queue pipeline. It verifies synthetic audio hashes
and attaches bounded evidence, without bundling weights or environments. Receipts
explicitly record CPU-only scope; passing this gate does not waive CUDA or owner
review requirements.

The owner confirmed that no Windows/NVIDIA GPU runner is configured. All results
above are CPU results. CUDA inference and owner-machine speed/memory remain
unverified; do not describe the final V0.8 acceptance as complete while required
hardware checks are outstanding. No failed check is bypassed by this document.
