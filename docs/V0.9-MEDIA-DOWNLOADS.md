# V0.9 Media Downloads candidate

V0.9 began as a dependent branch on complete V0.8 candidate
`e2d66c7281107283bc81d3fcd6ebaa0a13118a64`. While development was running, PR #8
merged; V0.9 then integrated approved main source
`078d9d5375033cf982e122f0c148433fe4e6760f`, including its experimental CUDA labels
and release guidance. Source/PR history and previous tags remain intact. A review
artifact is not a published release. V0.8's actual native CPU speech/model check passed in
[40402290962](https://github.com/BirthrightPublication/forge/actions/runs/40402290962);
its owner-approved hardware exception applies only to V0.8. V0.9 retains its own
review/publication requirements; CUDA remains experimental and unverified.

## Planning and execution

Media Downloads has Single Download, Channel Watch and Current Download Priority
views. Previously saved routes, presets, download worker types and Black Scripting
remain compatible. Processing Queue occupies the sidebar workspace position;
Settings is a footer utility, above the bottom-anchored Local Engine.

`download_plans.py` owns indexed additive SQLite plan, source-association and frozen
batch tables. `download_plan_api.py` owns persistent provider imports/selections
and authenticated planning/output routes. Source discovery, approval, resource
admission, actual transfer and verified completion are separate operations.
Playlist autosaves serialize the saved-record read, field merge and membership
changes in one transaction, preserving independent settings from concurrent saves.

Canonical provider/media identity deduplicates short links, channel discoveries and
manual submissions. Manual submission can upgrade a waiting channel plan without
duplicating its output. Existing verified completions are reused. Generic URLs
without provider identity use a normalized URL hash; no cross-platform identity is
invented. A browser selects saved provider entries, not arbitrary replacement URLs.

Waiting classes are manual single, manual playlist, then watched channel. Channel
priority is Ultra, Extra, High, Medium, Low, Minimal. Equal-priority channels take
deterministic fair turns; per-channel order uses real publication/view/duration
metadata, with Unknown last and deterministic ties. Card search/sort preferences
do not modify scheduling. Original playlist position survives selected standalone
downloads and filename expansion. Explicit custom playlist moves affect actual
admission, not just the displayed table.

`QueueManager` asks the planner for one atomic claim only after resource admission
succeeds, then launches it under the same scheduler lock. It does not preempt an
active transfer. Internal migrated `planned` queue rows preserve original IDs but
are omitted from executable/public queue lists until admission. Black Scripting
graph members retain their existing dependency records.

## Automation, folders and recovery

Fresh channels default to review. Instant Download approves new eligible
discoveries only; historical backlogs require explicit approval. Existing sources'
previous automation is migrated without erasing their prior decisions. Auth failures
suspend automatic checks; unrelated priority edits do not restart them. Polling
and monitoring stop with FORGE; startup refresh is asynchronous and bounded.

Watched channels use stable channel-specific directories and optional content-type
subdirectories under the chosen root. Existing legacy folder identities survive
renames. Manual links/playlists use the selected folder directly, with playlist
subfolders only on explicit selection. Destination changes never move old files.

Supported partial transfers remain in private application caches, with a request
identity and stable resume key. Failed attempts retain their original job history.
New attempts refer to the previous job's owned staging path and durable publication
journal; verified already-published files are reused without duplicating media.
HTTP Range continuation and ignored-Range restart are tested separately.

Startup reconciles abrupt interruptions and durable completion manifests. Explicit
user pauses/cancels remain respected; unrelated interrupted non-download work keeps
the existing queue safety pause. Controlled application shutdown does not turn an
otherwise running approved download schedule into a permanent user pause.

Completed plans require actual file/hash/media verification. At most two background
verification tasks share the configured disk budget and stop with the app. Missing
or fake legacy output is not silently counted as complete. Frozen batch membership
remains fixed; new discoveries stay in the live backlog. Review/failure items cannot
produce 100%; skipped resolution follows the chosen batch policy. Saved output
actions use plan/watch records and remain usable after queue-history cleanup.

## Interface and measured progress

Channel Watch uses compact responsive three/two/one-column cards with metric
containers, icon actions, priority/order controls and Instant toggles. The user's
illustration guides layout while FORGE's existing charcoal, gold and warm-white
theme remains. Unknown counts stay Unknown; illustrative subscriber/rate figures
are not copied into real application state.

Thumbnails are bounded, validated, authenticated internal previews with placeholders.
They are not exported, archived separately or placed beside downloaded media.
Playlist metadata and selections survive pagination/restart; long imports use
bounded metadata requests and planning chunks without growing the browser DOM.

yt-dlp hooks report actual bytes, known totals, speed and transfer ETA. Known
separate-stream totals may be aggregated; an unknown total keeps overall progress
indeterminate while clearly labeling a current-stream percentage. Merging, metadata
processing and media verification are separate stages. Stream completion never
marks the whole job complete. Existing FFmpeg processing and verified file references
continue feeding Black Scripting.

## Validation and candidate packaging

Automated suites cover actual SQLite migrations, state transitions, concurrent
claims, priorities/fairness/order, persistent imports, cancellation/restart intent,
batch denominators and publication recovery. Local HTTP media checks use real
yt-dlp/FFmpeg, Range/no-Range responses, separate-stream merging and an actually
terminated/restarted worker. Browser provider metadata and thumbnail transport
fixtures are explicitly synthetic; they are not evidence of live platform access.

Run the full Python suite and `tests/browser_v7_check.py`, `browser_v8_check.py`
and `browser_v9_check.py`, using disposable services and generated media. For
required native downloader evidence:

```powershell
python scripts/check_download_acceptance.py --require-windows --output "$env:TEMP\forge-v09-download-evidence"
```

The helper requires real dependencies and produces JUnit/JSON evidence. V0.9+ release
validation requires native Windows success from the exact clean tagged checkout,
with zero failed/skipped downloader cases. Historical pre-V0.9 tags remain compatible.

The populated upgrade harness is `tests/integration_upgrade_v9.py`; it uses the
installed updater, preserves V0.8 speech plus new plan/import/batch records, and
checks code-only rollback without restoring the database over newer user data.

The candidate names are `FORGE-v0.9.0-windows-x64.zip` and its `.zip.sha256`, with
one complete `app/` payload and all protected state/updater paths excluded. Legacy
`FORGE-v0.9.zip` remains available for offline updater compatibility. Packages are
review artifacts until owner approval and release workflows succeed.

Live YouTube availability/authentication and anti-bot policies are external
conditions, not guarantees. Resume depends on the actual protocol. No physical
CUDA or owner-machine performance claim is made by these media tests.
